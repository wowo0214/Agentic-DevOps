# A control workflow for shared laboratories

> A shared laboratory needs more than a remote button. The experiment should make its system visible before a student presses run.

## Start with a visible system

Every experiment should make the reference, controller, system, and measured feedback understandable before a student starts the run.

This is why the workflow begins with blocks and parameters rather than a hidden implementation. Students can describe what they expect before they compare it with what the equipment does.

## Make the important values explicit

Sampling time, gains, bounds, and experiment duration are part of the lesson. The interface keeps them close to the model so students can connect a change in a value with a change in the response.

The same structure gives instructors a common language when they review a result across different universities.

## Leave a trail

A remote experiment should produce a useful record: the configuration, the signals, and the exported data. A student can return to the result, compare runs, and explain what changed.

That trail turns expensive equipment into a repeatable learning environment rather than a one-time demonstration.
